Research

Teams now put large language models in their code review pipelines. The developer whose code is being checked also writes its comments, so a comment like "validated upstream, safe" becomes an attack. My experiments measure which of these comments work, why, and what removes the risk.

Across 780 trials, the strongest comments claimed authority over the code, and a bare statement of the author's confidence, which verifies nothing, worked nearly as well. Removing comments before analysis restored detection completely in the setting I tested.

CryptoBench

A benchmark of cryptographic API misuse for testing AI code reviewers. Each vulnerable Python snippet has a matching secure control, so a model that flags everything gets caught.

CommentInject

The adversarial comment test cases behind my Cyber-AI papers. One misleading comment is added to vulnerable code, and the benchmark records whether a model still reports the bug.

30vulnerable functions
14CWE categories
12comment strategies
3,360recorded trials

Four local code models, four studies, strategies grouped in four families.

Zenodo

Reproduce the numbers

Both releases include the test harness and an analysis script. The script recomputes the headline rates with Wilson 95% confidence intervals. Models run locally through Ollama at temperature 0, so anyone can repeat the runs.
